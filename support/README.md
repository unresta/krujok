# Бот тех. поддержки Krujok

Отдельный бот: свой токен, своя база, свой процесс. Главный бот про него не
знает и не зависит от него — если поддержка упадёт, кружочки продолжат крутиться.

Юзер пишет о проблеме в личку боту. Обращение падает карточкой в чат
поддержки. Модератор отвечает **обычным реплаем на карточку** — текст уходит
юзеру от имени бота. Ничего не нужно запоминать.

## Топики: по одному на обращение

Если включены (см. «Настройка топиков» ниже), каждое обращение получает
собственный топик с двух сторон:

- **у юзера в личке с ботом** — переписка по одному вопросу не смешивается с
  другими, старые обращения остаются отдельными ветками;
- **в чате операторов** — карточка, вложения, дополнения юзера и напоминания
  лежат в одном топике. Модератору достаточно **написать в топик, реплай не
  нужен** — тема сама говорит, о каком обращении речь.

Имя топика — `#12 · 💳 Оплата`, цвет иконки свой у каждой темы.

Всё это необязательно: без топиков бот работает точно как раньше — карточки
общей лентой, ответ реплаем. Старые обращения, созданные до включения
топиков, продолжают работать по реплаю.

## Как это выглядит

```
┌─ чат поддержки ────────────────────────┐
│ #обращение #12 · 🟡 ждёт ответа        │
│ Тема: 💳 Оплата                        │
│ От: 777 @vasya                         │
│ Когда: 5 мин назад                     │
│ ────────────────────────               │
│ Списалось 50 звёзд, монетки не пришли  │
│ 📎 фото                                │
│ ────────────────────────               │
│ В основном боте                        │
│ 🪙 Баланс: 42 · заработано 15          │
│ ⭐ Платежей: 2 на 70 звёзд             │
│    последний: 50⭐ → 150🪙, 6 мин назад │
│    ch_abc123                           │
│ 🎞 Кружки: 2 одобрено · 1 ждут         │
│ 👤 Анкета: approved · продано 2        │
│ [Взять] [Закрыть]                      │
│ [Шаблон] [Переписка]                   │
│ [Заблокировать]                        │
└────────────────────────────────────────┘
        ↑ реплай на карточку → ответ уходит юзеру
```

Номер платежа и баланс уже в карточке, поэтому на большинство обращений
можно ответить не переспрашивая.

## Что умеет юзер

- Шесть тем: оплата, монетки, анкета, кружок, вывод, другое.
- **Экран самопомощи** перед формой: частые случаи по выбранной теме
  разбираются без человека, кнопка «Не помогло» ведёт дальше.
- Текст до 1000 символов, можно приложить фото, видео, документ, голосовое
  или кружок. Одного скриншота достаточно — текст тогда не обязателен.
- Пока обращение открыто, любое следующее сообщение доклеивается к нему,
  а не создаёт новое.
- «Мои обращения» — список со статусами и всей перепиской.
- **Закрыть своё обращение самому**, если вопрос решился: кнопка есть в
  переписке и на экране «уже открыто обращение». Очередь не копит мёртвые
  вопросы, а лимит сразу освобождается под новое. Оценку в этом случае не
  просим — отвечать было некому. В чат уходит пометка, чтобы модератор не
  разбирал уже неактуальное.
- После ответа и закрытия модератором — оценка 👍/👎 одним тапом.
- Лимиты: одно открытое обращение и 5 новых в сутки.

## Что умеет админ

**В чате поддержки** (работает у любого, кто в этом чате):

- реплай на карточку → ответ юзеру, с вложением тоже;
- «Взять» — остальные видят, кто занят, и не отвечают вторыми;
- «Шаблон» — готовый ответ в один тап;
- «Переписка» — вся ветка;
- «Закрыть» — юзеру уходит просьба оценить;
- «Заблокировать» — только в поддержке, доступ к главному боту не меняется.

**`/admin` в личке** (только `SUPPORT_ADMIN_IDS`):

- очередь: кто ждёт дольше всех;
- статистика: среднее время первого ответа, доля 👍, обращения по темам;
- шаблоны: добавить, удалить, счётчик использований;
- поиск: по id юзера — его обращения и данные из главной базы; по номеру
  платежа из чека (`ch_…`) — сам платёж, сколько звёзд и монеток и был ли
  возврат. Для спорных оплат это главный инструмент;
- настройка чата с проверкой, что бот туда достаёт.

Плюс бот сам пингует чат, если обращение висит без ответа дольше 12 часов.

## Связь с главным ботом

Односторонняя и только на чтение. Telegram ID у человека один во всех ботах,
поэтому поддержка находит его в `bot.db` по `from_user.id` и добавляет в
карточку баланс, платежи, кружки, анкету и выплаты.

Защита двойная: том смонтирован `:ro`, а SQLite открывается с `mode=ro` —
запись отбивается на уровне драйвера. Проверено: попытка `UPDATE` падает с
`attempt to write a readonly database`.

Если `MAIN_DB_PATH` не задан, файла нет или в нём другая схема — поддержка
работает как обычно, просто без этих строк в карточке. Падать из-за главной
базы она не должна и не падает.

## Запуск в Docker

Из корня проекта, вместе с главным ботом:

```bash
cp support/.env.example support/.env
# заполнить SUPPORT_BOT_TOKEN, SUPPORT_CHAT, SUPPORT_ADMIN_IDS
docker compose up -d --build support
docker compose logs -f support
```

`MAIN_DB_PATH` и `SUPPORT_DB_PATH` в compose уже проставлены, в `.env` их
трогать не нужно.

## Запуск без Docker

```bash
cd support
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # заполнить
python bot.py
```

`MAIN_DB_PATH` тогда — путь до `bot.db` главного бота, например `../bot.db`
или `../data/bot.db`.

## Порядок настройки

1. Создать второго бота у @BotFather, забрать токен.
2. Создать группу для поддержки, добавить туда бота.
   Если в группе скрыты авторы сообщений, бот должен быть админом.
3. Узнать id группы (переслать оттуда сообщение в @userinfobot) и положить
   в `SUPPORT_CHAT` — либо задать потом в `/admin` → «Чат поддержки».
4. Свой id — в `SUPPORT_ADMIN_IDS`.
5. Запустить, открыть `/admin` и проверить строку статуса чата: должно быть
   «🟢 Бот на месте».
6. Добавить пару шаблонов на частые вопросы.

Если `SUPPORT_CHAT` не задан, карточки уходят в личку админам — работать
можно, но «Взять» теряет смысл, потому что коллеги не видят чужих карточек.

## Настройка топиков

Две независимые половины, обе включаются вручную — кодом это сделать нельзя.

**У юзера в личке.** Переключатель топик-режима в @BotFather для этого бота
(Bot API 9.4). Бот читает состояние через `getMe` при старте: если выключено,
топики в личке просто не создаются. В том же меню BotFather есть настройка,
разрешать ли юзерам самим создавать и удалять топики.

**В чате операторов.** Группа должна быть форумом (в настройках Telegram
включить «Topics»), а бот — админом с правом **«Управление темами»**
(`can_manage_topics`). Без права карточки идут в общую ленту, в логе будет
предупреждение.

Что получилось — видно в `/admin` строкой «Топики: у юзера 🟢 · в чате 🟢».
Если там 🔴, смотрите логи: бот пишет, чего именно не хватает.

Требования к версии: топики в личке — Bot API 9.4 (февраль 2026),
`message_thread_id` в личке — 9.3. Установленный aiogram 3.28.2 объявляет
API 10.0, так что обе части доступны.

## Важное про порядок роутеров

`bot.py` подключает их в порядке `admin → reply → user`, и это не случайно:
`handlers/user.py` заканчивается catch-all хендлером, который доклеивает
сообщение в открытое обращение. Если поставить его раньше, он съест ответы
модераторов.

По той же причине middleware проверяет бан **только в личных чатах**: в
главном боте похожая проверка идёт для всех апдейтов подряд, и групповое
сообщение от админа, который не жал `/start`, там утонуло бы в приветствии.

И третья ловушка, из-за топиков: `handlers/reply.py` ограничен группами (плюс
личка админов). Сообщение юзера в его личном топике выглядит на проводе так же,
как сообщение модератора в топике чата — обычный `Message` с
`message_thread_id`. Без этого фильтра reply-роутер съедал бы ответы юзера
раньше, чем до них доберётся `handlers/user.py`.
